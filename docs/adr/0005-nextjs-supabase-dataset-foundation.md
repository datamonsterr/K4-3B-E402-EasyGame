# One Next.js deployment with Supabase and explicit dataset provenance

The user selected Next.js for frontend and backend, Vercel for deployment, Supabase for the database, and confirmed dataset-first initialization. Use one application with frontend modules and server-only backend modules. Preserve the existing root static mock as a reference. Retain the Python starter's artifacts/tool organization and archive its original content, while implementing active EasyGame behavior in TypeScript.

The imported Discord labels are not unique identifiers and contain no trusted staff roles or real Discord links. Identify source rows by immutable dataset plus record ordinal, preserve unknown provenance, and require explicit notice verification. This costs additional import metadata but prevents silent record loss and fabricated authority. A separate Python backend or separate frontend/backend deployments would add an unnecessary deployment seam; automatic inference of notice authority would contradict grounded-answer requirements.

Implementation details and proposed resolutions of conflicting use cases are in [the foundation design](../architecture/NEXTJS_FOUNDATION_DESIGN.md) and [schema proposal](../architecture/DATABASE_SCHEMA.md). Those recommendations remain proposed until confirmed. Live Gateway ingestion and production notification delivery require subsequent integration work.
